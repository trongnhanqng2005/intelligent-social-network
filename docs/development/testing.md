# Testing strategy

## Test ownership

- **App-local tests (existing):** Nest Jest unit tests and Supertest API E2E remain under `apps/api`; React Vitest/RTL tests remain beside source under `apps/web/src`. Keep framework-specific behavior, component rendering and API-internal HTTP contract tests there. Do not migrate/duplicate them.
- **Posts & Feed Build checks:** API Jest covers Post normalization/cursors, repository query/invariant contracts, service policies, single-run writes and V5 migration/readiness source. The existing API-local Supertest suite uses in-memory persistence doubles for session/CSRF, parser limits and no-store behavior. Web Vitest/RTL covers the Post API projection, Unicode counter, composer, card edits/deletes, keyset Load More, route protection and friendship-triggered profile invalidation. While session revalidation is in flight and during ordinary Feed refresh, loaded drafts remain mounted; relationship-scope changes and confirmed 401 session revocation clear protected data. These checks do not verify Neo4j behavior or constitute Scenario Testing.
- **Root integration:** `tests/integration/api-proxy.test.mjs` launches the API and Vite dev server, calls `/api/health`, and verifies the forwarded HTTP/JSON response without a browser. The Weylume homepage no longer calls or displays health status; this infrastructure proxy contract is independent of the UI.
- **Root browser E2E:** Playwright Test scenarios live only in `tests/e2e/specs/`. The current foundation suite exercises real Chromium desktop and emulated mobile browsers against Playwright-managed API and Vite dev servers. It complements, rather than copies, app-local tests.
- **Weylume Scenario Testing (2026-10-14):** the approved Step 5 acceptance has adapted `foundation.spec.ts` to current homepage/navigation/not-found behavior while retaining the API proxy health check independently; `authentication.spec.ts` uses the current confirmation form, welcome/loading states, and accessible locators. See the WY-00–WY-12 evidence in [authentication acceptance](../../tests/e2e/authentication-acceptance.md). This run is distinct from the earlier redesign Build screenshots and did not reopen visual design.
- **Root unit:** `tests/unit/api-e2e-key-ownership.test.mjs` checks invocation-owned ephemeral-key cleanup, including concurrent invocation isolation and rejection of a mismatched ownership marker.
- Follow [tests/README.md](../../tests/README.md) for category ownership, browser locators, mock boundaries, data isolation, artifacts and feature-plan references.

The integration check uses Node 24's built-in [`node:test` runner](https://nodejs.org/docs/latest-v24.x/api/test.html). Browser QA uses pinned [`@playwright/test` 1.64.0](https://playwright.dev/docs/intro) and its matching Chromium build. Install that browser once with `npx playwright install chromium`. The foundation Playwright servers use strict ports 3301/5174; real-auth uses 3302/5175; profile uses 3305/5178; Friendship uses 3311/5181. Each refuses to reuse unrelated servers. Foundation browser/API contract tests set a non-routable dummy Neo4j endpoint and do not prove DB access. `test:neo4j:friendship-preflight` is the preserved read-only V1–V3 deployment gate before V4 migration; do not substitute it for the post-V4 current-schema FS-00 gate. The historical Friendship writer remains V4-gated and is not included in the current V5 auth/profile `test:neo4j` selection. Posts provisioning and migration are intentionally separate, serial steps behind `ISN_TEST_WRITE_WINDOW=owner-approved`; the integration suite never applies migrations or grants. Its real fixtures are limited to durable, exact synthetic ownership records; a failed cleanup leaves the manifest for recovery and fails the run. No database reset or broad graph cleanup is permitted. See [Neo4j operations](neo4j-operations.md).

The foundation browser config runs desktop Chromium and iPhone 13 mobile emulation on ports 3301/5174 with dummy Neo4j settings. Authentication browser QA uses a separate config on ports 3302/5175; it requires ignored `apps/api/.env.test.local`, verifies restricted identity/roles, V5 readiness and denied `isn-dev` access, uses ephemeral signing keys, and cleans only owned synthetic records. Auth screenshots and traces are disabled because inputs and requests can contain secrets; sanitized reports stay under ignored `.artifacts/playwright/`. Friendship's Step 5 saved browser run and interactive UI inspection are recorded in the Friendship acceptance/task records; this review did not execute a new browser run.

The profile browser config uses dedicated ports 3305/5178 and requires the same restricted real-DB safety gates as the auth browser config. It owns synthetic profile fixtures with durable, UUID-bound manifests and disables screenshots/traces. Its separate `npm run test:neo4j:profile-preflight` command is read-only; unlike the full `npm run test:neo4j` suite, it never invokes migration code. Friendship browser config uses ports 3311/5181, one worker and zero retries; its V4 preflight is read-only and its test owns UUID-bound user/pair/request/friendship fixtures with recovery manifests. See the [profile/discovery acceptance record](../../tests/e2e/user-profile-discovery-acceptance.md) and [Friendship acceptance record](../../tests/e2e/friendship-system-acceptance.md) for historical scenario evidence and limitations.

The Posts integration scenario exercises the production Posts and Friendship repositories/API against V5, including canonical accepted friendships on either side of the viewer ID, pending/rejected/cancelled states, current visibility across detail/profile/feed, deterministic keyset pages, friendship changes, optimistic mutation races, rollback, and a production-query EXPLAIN/PROFILE capture. Before it can write, the process requires the non-persisted `ISN_TEST_WRITE_WINDOW=owner-approved` invocation variable, exact restricted test settings, verified V5 readiness and the saved V4 preservation fingerprint. `npm run neo4j:migrate:posts-test` performs the read-only preflight, adds only 14 Post/AUTHORED grants, repeats preflight and applies V5 explicitly; do not start it without a confirmed exclusive window. The 2026-10-15 Build continuation ran this suite successfully and restored the recorded baseline. Its focused Playwright MCP visual inspection used web-only Vite plus a temporary GET-only mock API at desktop and narrow widths; it was not a real API test or Step 5 acceptance.

The API HTTP suite allocates one ephemeral key directory per Jest invocation in
ignored `apps/api/.artifacts`. Global teardown resolves that directory under the
allowlisted root and verifies its invocation marker before deleting only its own
keys. It never sweeps other runs' directories. The saved real-auth journeys also
check login/logout broadcasts to a second, unfocused page and registration/login
with 100 supplementary Unicode characters (200 UTF-16 code units).

Posts Step 5 has a separate current-V5 read-only gate and guarded runner. `npm run test:e2e:posts:list` is discovery-only. The saved Playwright config refuses direct execution and has no `webServer`; before the database preflight, the runner checks the exact worktree/branch, fresh `ISN_TEST_WRITE_WINDOW=owner-approved`, explicit `ISN_B_WORKLOAD_CLEAR=confirmed`, dedicated ports and measured resources. The subsequent read-only V5 preflight checks database identity/schema/grants/baseline and recovery-manifest state. Windows Stage A takes six 10-second samples and fails closed on incomplete measurements, three consecutive paging samples, unknown Spark/Docker/WSL state, any active Docker/WSL workload, or exhausted physical/commit headroom. It records the live machine baseline without forecasting from unrelated global Node/browser processes. Stage B starts the built API and one Vite process; Stage C measures those services with four browser contexts/five pages. Runtime reserve is the observed reduction in system-wide available physical memory and commit headroom from Stage A to each runtime stage; owned-process working-set/private-byte totals are retained as corroborating measurements, not summed as the reserve. This avoids both assumed workload multipliers and shared-page double counting. Stage C uses the immediately preceding verified, zero-workload Docker/WSL inventory from Stage B, because its browser-only child has a restricted environment; Spark/Java process state and system memory are still sampled during the browser probe. Playwright Test uses one worker and serial groups; MCP runs separately and is not added to the Playwright reserve. `--resource-probe-only` makes no database connection, skips the V5 preflight/business tests, and uses a dummy unreachable Neo4j endpoint to measure API/Web/browser startup. Runner-owned temp paths are invocation-local under ignored `.artifacts/.../tmp` (the runner checks the path is worktree-local and ignored before creating it). Only the full guarded runner creates test fixtures; it starts the built API rather than a compiler/watch process, uses zero retries and isolated contexts, and does not run migrations, provisioners or the incompatible `npm run test:neo4j` umbrella. The sanitized acceptance report is the evidence record for authorization, resource capacity, execution, cleanup and preservation.
